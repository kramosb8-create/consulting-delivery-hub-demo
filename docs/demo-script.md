# Guion de demo — 7 minutos

## 1. Problema
“En proyectos digitales, el riesgo no es solo desarrollar. El riesgo es perder el control de quién pidió qué, qué cambió y qué versión tiene el cliente.”

## 2. Dashboard ejecutivo
Mostrar KPIs, áreas, compromisos y estado. La vista es ejecutiva; GitHub conserva la evidencia técnica debajo.

## 3. Trazabilidad real
Abrir Issue #1 y luego PR #2 para mostrar el flujo necesidad → cambio → revisión.

## 4. Nueva solicitud
Registrar una necesidad con problema, valor esperado y criterios de aceptación.

## 5. Gobierno incorporado
Mostrar `.github/ISSUE_TEMPLATE`, `PULL_REQUEST_TEMPLATE.md`, `CODEOWNERS`, `workflows/quality.yml` y `CHANGELOG.md`.

## 6. Cierre comercial
“Con este esquema la consultoría no entrega solo una aplicación. Entrega un producto gobernado: con requerimientos, cambios, pruebas, responsables, versiones y conocimiento transferible.”
