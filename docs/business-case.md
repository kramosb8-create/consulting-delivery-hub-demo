# Caso de negocio: GitHub como sistema de gobierno del delivery digital

## Problema típico
En consultoría, los requerimientos suelen quedar repartidos entre correos, chats, Excel, minutas, documentos y conversaciones con desarrolladores. El resultado es pérdida de trazabilidad: no siempre es evidente quién pidió un cambio, por qué se hizo, qué se modificó, quién lo validó y qué versión llegó a producción.

## Propuesta
Usar GitHub como la capa de gobierno de los productos digitales de la consultoría:

**Necesidad → Issue → Rama → Pull Request → Pruebas → Aprobación → Release → Evidencia**

## Caso aplicado: FlowInvent / GEI
Este demo usa compromisos representativos de Mercadeo, Abastecimiento, Operaciones y Ventas. Cada compromiso tiene un identificador de negocio y una representación de su trazabilidad técnica.

## Beneficios ejecutivos
- Evidencia auditable de decisiones y cambios.
- Menor dependencia de una sola persona.
- Reutilización de componentes y mejores prácticas.
- Reducción de errores por cambios sin revisión.
- Visibilidad de backlog, bloqueos y progreso.
- Transferencia ordenada al cliente al cierre del proyecto.
